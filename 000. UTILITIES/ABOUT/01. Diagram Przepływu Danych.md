# Diagram Przepływu Danych

Główny diagram pokazujący całą architekturę projektu od inputów przez procesory do outputów i Power BI.

```mermaid
graph TB
    subgraph "INPUT - 300. INPUTS"
        MD1["📝 Teoria<br/>*.md (type: teoria)"]
        MD2["📝 Quiz<br/>*.md (type: quiz)"]
        MD3["📝 Gaps<br/>*.md (type: gaps)"]
    end

    subgraph "KONFIGURACJA"
        CONFIG["⚙️ config.md<br/>- Mapowanie CSS/JS<br/>- Typografia<br/>- Opcje generowania"]
        RESOURCES["📦 100. RESOURCES<br/>CSS + JS Templates"]
    end

    subgraph "PYTHON PROCESSORS - main.py"
        MAIN["🎯 main.py<br/>Orchestrator"]
        UTILS["🔧 utils.py<br/>Config + TMDL"]
        TEXT["📄 text_utils.py<br/>Markdown → HTML<br/>DAX Highlighting"]

        subgraph "Procesory Treści"
            TEORIA["📚 theory_processor.py<br/>Split by H1<br/>Multi-page measures"]
            QUIZ["❓ quiz_processor.py<br/>Interactive quizzes<br/>Validation logic"]
            GAPS["✏️ gaps_processor.py<br/>Fill-in-the-blank<br/>Slot validation"]
        end

        TEMPLATE["🎨 template_loader.py<br/>Load CSS/JS assets"]
    end

    subgraph "PROCESSING STAGES"
        STAGE1["📖 Stage 1: TEORIA<br/>1. Split by H1 headers<br/>2. Split by --- pages<br/>3. MD→HTML conversion<br/>4. Add navigation<br/>5. Create multi-page measure"]
        STAGE2["🎓 Stage 2: QUIZ<br/>1. Parse questions<br/>2. Extract answers<br/>3. Build validation<br/>4. Create interactive HTML<br/>5. Results summary"]
        STAGE3["📝 Stage 3: GAPS<br/>1. Parse tasks<br/>2. Extract SLOTs<br/>3. Build drop zones<br/>4. Add validation<br/>5. Feedback system"]
    end

    subgraph "OUTPUT - 400. OUTPUTS"
        HTML1["📄 Section1.html<br/>Section2.html<br/>..."]
        HTML2["📄 Quiz.html"]
        HTML3["📄 Gaps.html"]

        subgraph "_Measures Folder"
            TMDL["📋 _HTML.md<br/>TMDL with all measures"]
            PARAM["📊 _Parametr.md<br/>Parameter table"]
        end
    end

    subgraph "FINAL TARGET"
        PBI["💼 Power BI Desktop<br/>Import TMDL files"]
    end

    %% Input flows
    MD1 --> MAIN
    MD2 --> MAIN
    MD3 --> MAIN
    CONFIG --> UTILS
    RESOURCES --> TEMPLATE

    %% Processing flows
    MAIN --> UTILS
    MAIN --> TEMPLATE
    UTILS --> TEXT

    MAIN -->|type=teoria| TEORIA
    MAIN -->|type=quiz| QUIZ
    MAIN -->|type=gaps| GAPS

    TEORIA --> STAGE1
    QUIZ --> STAGE2
    GAPS --> STAGE3

    TEXT --> TEORIA
    TEXT --> QUIZ
    TEXT --> GAPS

    TEMPLATE --> TEORIA
    TEMPLATE --> QUIZ
    TEMPLATE --> GAPS

    %% Output flows
    STAGE1 --> HTML1
    STAGE2 --> HTML2
    STAGE3 --> HTML3

    HTML1 --> TMDL
    HTML2 --> TMDL
    HTML3 --> TMDL

    HTML1 --> PARAM
    HTML2 --> PARAM
    HTML3 --> PARAM

    TMDL --> PBI
    PARAM --> PBI

    %% Styling
    classDef inputClass fill:#e1f5ff,stroke:#0078d4,stroke-width:2px
    classDef configClass fill:#fff4ce,stroke:#f4a300,stroke-width:2px
    classDef processClass fill:#d4edda,stroke:#28a745,stroke-width:2px
    classDef stageClass fill:#f8d7da,stroke:#dc3545,stroke-width:2px

    class MD1,MD2,MD3 inputClass
    class CONFIG,RESOURCES configClass
    class MAIN,UTILS,TEXT,TEORIA,QUIZ,GAPS,TEMPLATE processClass
    class STAGE1,STAGE2,STAGE3 stageClass
    class HTML1,HTML2,HTML3,TMDL,PARAM outputClass
    class PBI finalClass
```

## Opis

Ten diagram przedstawia kompletny ekosystem projektu:

- **INPUT**: Trzy typy plików Markdown (teoria, quiz, gaps) z folderu 300. INPUTS
- **KONFIGURACJA**: config.md steruje mapowaniem CSS/JS, a folder 100. RESOURCES zawiera szablony
- **PROCESORY**: 7 modułów Python współpracujących ze sobą
- **ETAPY**: Trzy specjalizowane ścieżki przetwarzania dla różnych typów treści
- **OUTPUT**: Wygenerowane pliki HTML + TMDL gotowe do importu do Power BI

# Budowa Quiz - Type: quiz

Szczegółowy opis budowy interaktywnych quizów z walidacją odpowiedzi.

## 📋 Frontmatter

```yaml
---
type: quiz
---
```

**Obowiązkowe.** Określa typ treści jako quiz.

---

## 🏗️ Struktura Pliku

### Nagłówek Główny (`# Quiz: Nazwa`)

```markdown
# Quiz: Podstawy DAX
```

**Funkcja:** Tytuł quizu wyświetlany na górze interfejsu.

**Output:** Jeden plik HTML z interaktywnym quizem.

**Uwaga:** W przeciwieństwie do teorii, quiz **nie dzieli się** na osobne miary. Wszystkie pytania są w jednym pliku.

---

## ❓ Struktura Pytania

### Kompletny Blok Pytania

```markdown
## Pytanie 1
**Jaka funkcja sumuje wartości w kolumnie?**
- A) AVERAGE
- B) COUNT
- C) SUM
- D) MAX
---
correct: 2
explanation: SUM jest funkcją agregującą, która sumuje wszystkie wartości numeryczne w określonej kolumnie.
---
```

### Elementy Składowe

#### 1. Nagłówek Pytania (`## Pytanie X`)

```markdown
## Pytanie 1
```

**Funkcja:** Numeracja pytań (wyświetlana w interfejsie).

**Konwencja:** `Pytanie 1`, `Pytanie 2`, `Pytanie 3`, etc.

#### 2. Treść Pytania (**Bold**)

```markdown
**Jaka funkcja sumuje wartości w kolumnie?**
```

**WAŻNE:** Treść pytania **MUSI** być otoczona podwójnym asterixem (`**...**`).

**Przykłady:**

✅ **DOBRZE:**
```markdown
**Która funkcja oblicza średnią?**
**Co robi funkcja CALCULATE?**
**Wybierz poprawną składnię funkcji SUM.**
```

❌ **ŹLE:**
```markdown
Która funkcja oblicza średnią?  (brak bold)
*Która funkcja oblicza średnią?*  (pojedynczy asterix - italic)
```

#### 3. Odpowiedzi (Lista z Literami)

```markdown
- A) AVERAGE
- B) COUNT
- C) SUM
- D) MAX
```

**Zasady:**
- Każda odpowiedź w osobnej linii
- Rozpoczynaj od bullet point (`-`)
- Format: `Litera)` + spacja + treść odpowiedzi
- Standardowo: A, B, C, D (możesz więcej lub mniej)

**Przykłady:**

✅ **Quiz z 3 odpowiedziami:**
```markdown
- A) TAK
- B) NIE
- C) NIE WIEM
```

✅ **Quiz z 5 odpowiedziami:**
```markdown
- A) SUM
- B) AVERAGE
- C) COUNT
- D) MAX
- E) MIN
```

#### 4. Separator (`---`)

```markdown
---
```

**Funkcja:** Oddziela pytanie od metadanych (correct, explanation).

#### 5. Słowo Kluczowe: `correct:`

```markdown
correct: 2
```

**Funkcja:** Określa **indeks poprawnej odpowiedzi** (liczony od 0).

**Mapowanie:**

| Indeks | Odpowiedź |
|--------|-----------|
| `0` | A |
| `1` | B |
| `2` | C |
| `3` | D |
| `4` | E |

**Przykłady:**

```markdown
- A) AVERAGE
- B) SUM  ← Poprawna
- C) COUNT
---
correct: 1  ← Indeks B = 1 (liczone od 0)
```

```markdown
- A) TRUE  ← Poprawna
- B) FALSE
---
correct: 0  ← Indeks A = 0
```

#### 6. Słowo Kluczowe: `explanation:`

```markdown
explanation: SUM sumuje wszystkie wartości w kolumnie. AVERAGE oblicza średnią, COUNT liczy wiersze, a MAX zwraca maksimum.
```

**Funkcja:** Wyjaśnienie pokazywane **po udzieleniu odpowiedzi** (zarówno poprawnej jak i błędnej).

**Formatowanie w explanation:**
- Możesz używać Markdown (bold, italic)
- Możesz używać `inline code`
- **Nie** używaj bloków kodu ` ```dax ` (lepiej inline)

**Przykład z formatowaniem:**

```markdown
explanation: Funkcja **SUM** sumuje wartości, podczas gdy `AVERAGE` oblicza średnią arytmetyczną. To fundamentalna różnica w DAX.
```

#### 7. Separator Końcowy (`---`)

```markdown
---
```

**Funkcja:** Oddziela pytania od siebie.

## 📖 Przykład Kompletnego Quizu

```markdown
---
type: quiz
---

# Quiz: Funkcje Agregujące DAX

## Pytanie 1
**Która funkcja oblicza sumę wartości w kolumnie?**
- A) AVERAGE
- B) COUNT
- C) SUM
- D) MAX
---
correct: 2
explanation: **SUM** jest podstawową funkcją agregującą w DAX, która sumuje wszystkie wartości numeryczne w określonej kolumnie. AVERAGE oblicza średnią, COUNT liczy wiersze, a MAX zwraca wartość maksymalną.
---

## Pytanie 2
**Która funkcja służy do liczenia wierszy w tabeli?**
- A) SUM
- B) COUNTROWS
- C) CALCULATE
- D) FILTER
---
correct: 1
explanation: **COUNTROWS** jest funkcją do liczenia wierszy w tabeli lub zbiorze danych. SUM sumuje wartości, CALCULATE modyfikuje kontekst, a FILTER filtruje tabelę.
---

## Pytanie 3
**Co robi funkcja CALCULATE?**
- A) Oblicza sumę wartości
- B) Liczy wiersze w tabeli
- C) Modyfikuje kontekst filtra
- D) Tworzy nową tabelę
---
correct: 2
explanation: **CALCULATE** to kluczowa funkcja w DAX służąca do **modyfikowania kontekstu filtra** podczas obliczania wyrażenia. Nie oblicza sumy ani nie liczy wierszy - to robi wyrażenie wewnątrz CALCULATE.
---

## Pytanie 4
**Jaki będzie wynik: `AVERAGE(Sales[Amount])` jeśli wartości to: 100, 200, 300?**
- A) 600
- B) 200
- C) 150
- D) 300
---
correct: 1
explanation: AVERAGE oblicza **średnią arytmetyczną**: (100 + 200 + 300) / 3 = 600 / 3 = **200**.
---
```

**Output:**
- `Quiz - Funkcje Agregujące DAX.html`
- Interaktywny quiz z 4 pytaniami
- Nawigacja między pytaniami (Next/Previous)
- Walidacja odpowiedzi po kliknięciu
- Wyświetlanie wyjaśnień
- Podsumowanie wyników na końcu (X z 4 poprawnych)

## 🎯 Specjalne Przypadki

### Quiz z 2 Odpowiedziami (True/False)

```markdown
## Pytanie 1
**Funkcja SUM może sumować teksty?**
- A) TAK
- B) NIE
---
correct: 1
explanation: SUM działa tylko na wartościach numerycznych. Próba sumowania tekstów zwróci błąd.
---
```

### Quiz z Kodem DAX w Pytaniu

```markdown
## Pytanie 3
**Co zwróci `COUNTROWS(Sales)` jeśli tabela Sales ma 100 wierszy?**
- A) 0
- B) 1
- C) 100
- D) Błąd
---
correct: 2
explanation: `COUNTROWS` liczy wszystkie wiersze w tabeli, więc wynik to 100.
---
```

### Quiz z Formatowaniem w Odpowiedziach

```markdown
## Pytanie 5
**Która składnia jest poprawna?**
- A) `SUM[Sales]`
- B) `SUM(Sales[Amount])`
- C) `SUM Sales[Amount]`
- D) `SUM.Sales[Amount]`
---
correct: 1
explanation: Poprawna składnia to `SUM(Sales[Amount])` - funkcja z nawiasami i pełną ścieżką do kolumny.
---
```

## 💡 Wskazówki i Best Practices

### ✅ DO (Rób tak)

1. **Jasne pytania:**
   ```markdown
   **Która funkcja sumuje wartości?**  ← Jasne
   ```

2. **Konkretne odpowiedzi:**
   ```markdown
   - A) SUM
   - B) AVERAGE
   - C) COUNT
   ```

3. **Wyjaśnienia z kontekstem:**
   ```markdown
   explanation: SUM sumuje wartości numeryczne. W przeciwieństwie do SUMX, SUM nie iteruje po wierszach tylko operuje na kolumnie.
   ```

4. **Odpowiednia liczba pytań:**
   - 5-10 pytań: ✅ Optymalne
   - 10-15 pytań: ⚠️ Długie, ale OK
   - 15+: ❌ Za długie, rozważ podział

5. **Różnorodność trudności:**
   ```markdown
   # Quiz: Podstawy DAX
   ## Pytanie 1  ← Łatwe
   ## Pytanie 2  ← Średnie
   ## Pytanie 3  ← Trudne
   ```

### ❌ DON'T (Nie rób tego)

1. **Niejednoznaczne pytania:**
   ```markdown
   **Co robi ta funkcja?**  ← Która funkcja?
   ```

2. **Zbyt podobne odpowiedzi:**
   ```markdown
   - A) Sumuje wartości
   - B) Oblicza sumę
   - C) Dodaje wartości  ← Za podobne!
   ```

3. **Brak wyjaśnienia:**
   ```markdown
   explanation: SUM  ← Za krótkie!
   ```

4. **Zbyt długie pytania:**
   ```markdown
   **Jeśli mamy tabelę Sales z kolumnami Amount, Date, Product, i chcemy obliczyć całkowitą sprzedaż dla roku 2023, ale tylko dla produktów z kategorii Electronics, które były sprzedane w miesiącach letnich (czerwiec-sierpień), to którą funkcję użyjemy jako zewnętrzną?**
   ← Za długie! Uprość.
   ```

5. **Błędne indeksowanie:**
   ```markdown
   - A) Odpowiedź 1
   - B) Odpowiedź 2  ← Poprawna
   ---
   correct: 2  ← ZŁE! Powinno być 1 (B = indeks 1)
   ```

## 🔍 Debugowanie Problemów

### Problem: "Pytanie nie ma bold"

**Przyczyna:** Brak `**` wokół pytania
```markdown
## Pytanie 1
Jaka funkcja sumuje?  ← ZŁE
```

**Rozwiązanie:**
```markdown
## Pytanie 1
**Jaka funkcja sumuje?**  ← DOBRE
```

### Problem: "Niepoprawna odpowiedź jest oznaczona jako poprawna"

**Przyczyna:** Błędny indeks w `correct:`
```markdown
- A) Błąd
- B) Błąd
- C) Poprawna  ← To jest indeks 2 (A=0, B=1, C=2)
---
correct: 3  ← ZŁE! (indeks 3 to D, którego nie ma)
```

**Rozwiązanie:**
```markdown
correct: 2  ← DOBRE (C = indeks 2)
```

### Problem: "Wyjaśnienie się nie wyświetla"

**Przyczyna:** Brak słowa kluczowego `explanation:`
```markdown
---
correct: 1
SUM sumuje wartości  ← ZŁE (brak keyword)
---
```

**Rozwiązanie:**
```markdown
---
correct: 1
explanation: SUM sumuje wartości  ← DOBRE
---
```

### Problem: "Quiz nie generuje się"

**Przyczyna 1:** Brak frontmatter
```markdown
# Quiz: Test  ← ZŁE (brak frontmatter)
```

**Rozwiązanie:**
```markdown
---
type: quiz  ← DOBRE
---
# Quiz: Test
```

**Przyczyna 2:** Brak separatora między pytaniami
```markdown
## Pytanie 1
...
correct: 0
explanation: ...
## Pytanie 2  ← ZŁE (brak ---)
```

**Rozwiązanie:**
```markdown
## Pytanie 1
...
correct: 0
explanation: ...
---  ← DOBRE
## Pytanie 2
```

| Element | Składnia | Funkcja | Wymagane |
|---------|----------|---------|----------|
| **Frontmatter** | `type: quiz` | Określa typ | ✅ TAK |
| **Tytuł** | `# Quiz: Nazwa` | Nagłówek quizu | ✅ TAK |
| **Pytanie** | `## Pytanie X` | Numeracja | ✅ TAK |
| **Treść pytania** | `**Pytanie?**` | Bold text | ✅ TAK |
| **Odpowiedzi** | `- A) ...` | Lista opcji | ✅ TAK |

| **Correct** | `correct: 2` | Indeks poprawnej (0-based) | ✅ TAK |
| **Explanation** | `explanation: ...` | Wyjaśnienie | ✅ TAK |

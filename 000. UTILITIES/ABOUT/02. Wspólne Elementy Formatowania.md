# Wspólne Elementy Formatowania

Elementy wspólne dla wszystkich typów treści (Teoria, Quiz, Gaps).

## 📝 Frontmatter YAML

Każdy plik **MUSI** zaczynać się od frontmatter określającego typ treści:

```yaml
---
type: teoria | quiz | gaps
---
```

### Przykłady:

**Teoria:**
```yaml
---
type: teoria
---
```

**Quiz:**
```yaml
---
type: quiz
---
```

**Gaps:**
```yaml
---
type: gaps
---
```

**UWAGA:** Frontmatter jest **obowiązkowy**. Bez niego procesor nie będzie wiedział jak przetworzyć plik.

## 📐 Formatowanie Markdown

Wszystkie typy treści wspierają standardowe formatowanie Markdown:

### Bold (Pogrubienie)
```markdown
**Pogrubiony tekst**
```
Wynik: **Pogrubiony tekst**

### Italic (Kursywa)
```markdown
*Tekst kursywą*
```
Wynik: *Tekst kursywą*

### Kod Inline
```markdown
Użyj funkcji `SUM` do sumowania wartości.
```
Wynik: Użyj funkcji `SUM` do sumowania wartości.

### Listy Punktowane
```markdown
- Pierwszy element
- Drugi element
- Trzeci element
```
Wynik:
- Pierwszy element
- Drugi element
- Trzeci element

### Listy Numerowane
```markdown
1. Pierwszy krok
2. Drugi krok
3. Trzeci krok
```
Wynik:
1. Pierwszy krok
2. Drugi krok
3. Trzeci krok

### Listy Zagnieżdżone
```markdown
- Element główny
  - Podelement 1
  - Podelement 2
- Inny element główny
```
Wynik:
- Element główny
  - Podelement 1
  - Podelement 2
- Inny element główny

## 💻 Bloki Kodu DAX

Wszystkie typy wspierają bloki kodu DAX z automatycznym podświetlaniem składni:

````markdown
```dax
Total Sales =
    CALCULATE(
        SUM(Sales[Amount]),
        Sales[Year] = 2023
    )
```
````

### Co jest automatycznie podświetlane:

| Element | Przykład | Kolor |
|---------|----------|-------|
| **Keywords** | `VAR`, `RETURN` | Niebieski (keyword) |
| **Functions** | `SUM`, `CALCULATE`, `FILTER` | Zielony (function) |
| **Numbers** | `100`, `3.14`, `2023` | Pomarańczowy (number) |
| **Comments** | `-- komentarz` | Szary (comment) |
| **Strings** | `"tekst"` | Czerwony (string) |

### Przykład z komentarzami:

````markdown
```dax
-- Obliczanie całkowitej sprzedaży
Total Sales =
    VAR CurrentYear = YEAR(TODAY())  -- Aktualny rok
    RETURN
        CALCULATE(
            SUM(Sales[Amount]),
            Sales[Year] = CurrentYear
        )
```
````

**Wynik:** Kod z podświetloną składnią i komentarzami w szarym kolorze.

## 🖼️ Obrazy (Wikilinks)

Obsługa obrazów przez Obsidian wikilinks z automatyczną konwersją do GitHub URLs:

### GIF (animacje)
```markdown
![[demo.gif]]
```

**Konwersja:**
```
https://raw.githubusercontent.com/[user]/[repo]/main/bin/grafiki-do-szkolenia/demo.gif
```

**Zastosowanie:** Animacje, demonstracje krok po kroku

### PNG/JPG (obrazy statyczne)
```markdown
![[chart.png]]
```

**Konwersja:**
```
https://github.com/[user]/[repo]/blob/main/bin/chart.png
```

**Zastosowanie:** Wykresy, diagramy, zrzuty ekranu

### Proces dodawania obrazów:

1. **Wstaw szablon obrazu**
   - Skrót: `Alt+Shift+1` (Obsidian templates)
   - Wybierz: `0. Embed GIF.md` lub `0. Embed PNG.md`

2. **Umieść plik w odpowiednim folderze:**
   - GIF → `bin/grafiki-do-szkolenia/nazwa.gif`
   - PNG/inne → `bin/nazwa.png`

3. **Wyślij na GitHub:**
   - `Ctrl+P` → `Git: Commit`
   - `Ctrl+P` → `Git: Push`

4. **Użyj w treści:**
   ```markdown
   ![[nazwa.gif]]
   ```

## 🔤 Znaki Specjalne i Typografia

Automatyczna zamiana znaków na polskie odpowiedniki typograficzne:

### Cudzysłowy
```markdown
Input:  "tekst w cudzysłowie"
Output: "tekst w cudzysłowie"
```

### Apostrofy
```markdown
Input:  'tekst z apostrofem'
Output: ‛tekst z apostrofem'
```

### Konfiguracja (config.md)
```json
{
  "characters": {
    "quote": """,
    "single_quote": "‛"
  }
}
```

**UWAGA:** Możesz zmienić znaki w `config.md` jeśli potrzebujesz innych znaków typograficznych.

## 💬 Komentarze w DAX

Komentarze są automatycznie rozpoznawane i stylowane:

### Komentarz jednoliniowy
```dax
-- To jest komentarz
Total = SUM(Sales[Amount])
```

### Komentarz inline
```dax
Total = SUM(Sales[Amount])  -- Suma sprzedaży
```

### Komentarz blokowy (nieobsługiwany bezpośrednio)
```dax
/*
To jest komentarz blokowy.
Obsługiwany przez DAX, ale procesor traktuje go jak tekst.
*/
```

**UWAGA:** Procesor najlepiej obsługuje komentarze `--`. Komentarze blokowe `/* */` są obsługiwane przez DAX, ale mogą nie mieć specjalnego formatowania w HTML.

## 📋 Nagłówki

Różne poziomy nagłówków mają różne funkcje w zależności od typu:

| Nagłówek | Teoria | Quiz | Gaps |
|----------|--------|------|------|
| `# H1` | **Split na osobne miary** | Tytuł quizu | Tytuł zadania |
| `## H2` | Podsekcje w ramach strony | **Pytanie** (`## Pytanie X`) | **Sekcje** (`## Dostępne funkcje`) |
| `### H3` | Mniejsze podsekcje | Rzadko używane | Rzadko używane |

**Szczegóły:** Zobacz osobne pliki dla każdego typu (02a, 02b, 02c).

## ⚠️ Znaki Specjalne do Unikania

Niektóre znaki wymagają escapowania lub mogą powodować problemy:

### Bezpieczne (bez escapowania)
- Bold: `**text**`
- Italic: `*text*`
- Code: `` `text` ``

### Wymagające uwagi
- `<` i `>` → Automatycznie escapowane do `&lt;` i `&gt;`
- `"` w HTML → Automatycznie escapowane do `'` (apostrof)

**Procesor automatycznie obsługuje escapowanie, nie musisz się tym martwić.**

## 📊 Podsumowanie - Co Działa Wszędzie

✅ **Wspierane przez wszystkie typy:**
- Frontmatter `type: teoria/quiz/gaps`
- Formatowanie: bold, italic, kod inline
- Listy punktowane i numerowane
- Bloki kodu DAX z podświetlaniem
- Obrazy przez wikilinks (GIF, PNG)
- Typografia polska (cudzysłowy, apostrofy)
- Komentarze DAX (`--`)
- Linki

❌ **Nieobsługiwane:**
- Tabele Markdown (rzadko potrzebne)
- Checkboxy `- [ ]` (brak interaktywności w Power BI)
- Emoji (lepiej używać Unicode: ✅ ❌ ⚠️)

---

## 💡 Wskazówki

1. **Używaj prostego formatowania** - Power BI HTML ma ograniczenia, unikaj skomplikowanych layoutów
2. **Testuj obrazy na GitHub** - Upewnij się, że obrazy są dostępne publicznie
3. **DAX zawsze w blokach `dax`** - To zapewnia podświetlanie składni
4. **Komentarze pomagają** - Używaj `--` do wyjaśniania kodu DAX
5. **Nie używaj HTML bezpośrednio** - Procesor generuje HTML, pisz tylko Markdown

# Budowa Teorii - Type: teoria

Szczegółowy opis budowy treści teoretycznych z nawigacją multi-page.

## 📋 Frontmatter

```yaml
---
type: teoria
---
```

**Obowiązkowe.** Określa typ treści jako teoria.

---

## 🏗️ Struktura Pliku

### Nagłówki H1 (`#`) - Split na Osobne Miary

```markdown
# Funkcje Agregujące
treść sekcji...

# Funkcje Tekstowe
treść sekcji...

# Funkcje Dat
treść sekcji...
```

**Funkcja:** Każdy nagłówek `H1` tworzy **osobną miarę HTML** (osobny plik w 400. OUTPUTS).

### Przykład Input → Output

**Input:** `01. Podstawy DAX.md`
```markdown
---
type: teoria
---

# Funkcje Agregujące
Treść o SUM, AVERAGE...

# Funkcje Tekstowe
Treść o CONCATENATE, LEFT...

# Funkcje Dat
Treść o TODAY, YEAR...

# Funkcje Logiczne
Treść o IF, AND, OR...
```

**Output:** 4 osobne pliki HTML:
```
400. OUTPUTS/Szkolenie/Moduł/
├── 01. Podstawy DAX - Funkcje Agregujące.html
├── 01. Podstawy DAX - Funkcje Tekstowe.html
├── 01. Podstawy DAX - Funkcje Dat.html
└── 01. Podstawy DAX - Funkcje Logiczne.html
```

**Każdy plik** to osobna miara Power BI gotowa do importu.

---

## 📄 Separator Stron (`---`) - Multi-page Navigation

```markdown
# Funkcje Agregujące

Strona 1: Wprowadzenie
Treść pierwszej strony...

---

Strona 2: SUM w praktyce
Treść drugiej strony...

---

Strona 3: AVERAGE i inne
Treść trzeciej strony...
```

**Funkcja:** Separator `---` dzieli treść **wewnątrz jednej miary** na osobne strony.

**Wynik:**
- Jedna miara HTML: `Funkcje Agregujące.html`
- 3 strony z nawigacją "Previous" / "Next"
- Licznik strony: "Strona 1 z 3"

### Jak Działa Nawigacja?

Użytkownik w Power BI widzi:
```
┌─────────────────────────────────────┐
│  Funkcje Agregujące                 │
├─────────────────────────────────────┤
│  Strona 1 z 3                       │
│                                     │
│  Wprowadzenie                       │
│  Treść pierwszej strony...          │
│                                     │
├─────────────────────────────────────┤
│  [Previous]    [Next]               │
└─────────────────────────────────────┘
```

Kliknięcie "Next" pokazuje stronę 2 (bez przeładowania miary).

## 🎨 Komponenty Teorii

### 1. Nagłówek H2 (`##`) - Podsekcje

```markdown
# Funkcje Agregujące

## SUM - Sumowanie wartości
Opis funkcji SUM...

## AVERAGE - Średnia
Opis funkcji AVERAGE...
```

**Funkcja:** Organizacja treści w ramach jednej strony.

**Nie tworzy** osobnych miar ani stron - to tylko formatowanie wewnętrzne.

### 2. Bloki Kodu DAX

````markdown
```dax
Total Sales =
    SUM(Sales[Amount])
```
````

**Automatyczne podświetlanie:**
- Keywords: `VAR`, `RETURN` → niebieski
- Functions: `SUM`, `CALCULATE` → zielony
- Numbers: `100`, `2023` → pomarańczowy
- Comments: `-- komentarz` → szary

### 3. Obrazy

```markdown
![[sum_example.gif]]
```

**Typy:**
- GIF (bin/grafiki-do-szkolenia/) → animacje
- PNG (bin/) → wykresy, diagramy

**Konwersja:** Automatyczna do GitHub URLs (raw.githubusercontent.com lub github.com/blob/main)

### 4. Formatowanie Tekstu

```markdown
**Pogrubienie** - dla ważnych terminów
*Kursywa* - dla akcentów
`inline code` - dla krótkich snippetów kodu
```

### 5. Listy

```markdown
Funkcje agregujące:
- SUM - sumowanie
- AVERAGE - średnia
- COUNT - liczenie
- MAX/MIN - wartości ekstremalne
```

## 📐 Zasady Organizacji Stron

### Kiedy używać H1 (osobna miara)?

✅ **TAK - Oddzielna miara:**
- Różne tematy/kategorie (Funkcje Agregujące vs Funkcje Tekstowe)
- Niezależne sekcje szkolenia
- Różne poziomy trudności w tym samym module

❌ **NIE - Ta sama miara:**
- Różne przykłady tego samego tematu
- Kroki w ramach jednego procesu
- Kontynuacja opisu (część 1, 2, 3)

### Kiedy używać `---` (osobna strona)?

✅ **TAK - Osobna strona:**
- Zbyt dużo treści na jednej stronie (>500 słów)
- Logiczne etapy (teoria → przykład → ćwiczenie)
- Różne aspekty tego samego tematu

❌ **NIE - Ta sama strona:**
- Krótkie opisy (poniżej 300 słów)
- Powiązane informacje (definicja + przykład)
- Lista z wyjaśnieniami

### Optymalna Liczba Stron

| Strony | Ocena | Uwagi |
|--------|-------|-------|
| 1-3 | ✅ Optymalne | Łatwa nawigacja, szybki dostęp |
| 4-7 | ⚠️ Akceptowalne | Może wymagać więcej kliknięć |
| 8+ | ❌ Za dużo | Rozważ split na osobne miary (H1) |

## 📖 Przykład Kompletnej Teorii

```markdown
---
type: teoria
---

# Funkcje Agregujące

Funkcje agregujące w DAX służą do obliczania wartości zbiorczych na podstawie zestawów danych.

## SUM - Sumowanie Wartości

Funkcja `SUM` sumuje wszystkie wartości numeryczne w kolumnie.

**Składnia:**
```dax
SUM(<kolumna>)
```

**Przykład:**
```dax
Total Sales = SUM(Sales[Amount])
```

![[sum_visualization.gif]]

---

## Przykłady Zaawansowane

### SUM z CALCULATE

Możesz użyć SUM wewnątrz CALCULATE do filtrowania:

```dax
Sales 2023 =
    CALCULATE(
        SUM(Sales[Amount]),
        YEAR(Sales[Date]) = 2023
    )
```

### SUM z warunkami

Użyj SUMX dla warunków per row:

```dax
High Value Sales =
    SUMX(
        FILTER(Sales, Sales[Amount] > 1000),
        Sales[Amount]
    )
```

![[sum_advanced_example.png]]

---

## Ćwiczenie Praktyczne

**Zadanie:** Oblicz całkowitą sprzedaż dla produktów z kategorii "Electronics".

**Wskazówka:** Użyj `CALCULATE` z filtrem na kolumnę `Product[Category]`.

**Rozwiązanie:**
```dax
Electronics Sales =
    CALCULATE(
        SUM(Sales[Amount]),
        Product[Category] = "Electronics"
    )
```

---

# Funkcje Tekstowe

Funkcje tekstowe w DAX pozwalają na manipulację i transformację wartości tekstowych.

## CONCATENATE - Łączenie Tekstów

Funkcja `CONCATENATE` łączy dwa teksty w jeden.

**Składnia:**
```dax
CONCATENATE(<tekst1>, <tekst2>)
```

**Przykład:**
```dax
Full Name =
    CONCATENATE(
        Customer[FirstName],
        " " & Customer[LastName]
    )
```

---

## Alternatywne Podejście: Operator &

Zamiast CONCATENATE możesz użyć operatora `&`:

```dax
Full Name = Customer[FirstName] & " " & Customer[LastName]
```

**Zalety operatora &:**
- Krótszy zapis
- Można łączyć więcej niż 2 elementy
- Bardziej czytelny kod

**Przykład z wieloma elementami:**
```dax
Full Address =
    Customer[Street] & ", " &
    Customer[City] & " " &
    Customer[PostalCode]
```

![[concatenate_example.gif]]
```

**Output:**
- `Funkcje Agregujące.html` (3 strony: Wprowadzenie → Przykłady → Ćwiczenie)
- `Funkcje Tekstowe.html` (2 strony: CONCATENATE → Operator &)

## 💡 Wskazówki i Best Practices

### ✅ DO (Rób tak)

1. **Używaj H1 dla głównych tematów**
   ```markdown
   # Wprowadzenie do CALCULATE
   # Modyfikowanie Kontekstu
   # Time Intelligence
   ```

2. **Separator `---` dla logicznych podziałów**
   ```markdown
   # Temat
   Wprowadzenie...
   ---
   Przykłady...
   ---
   Ćwiczenia...
   ```

3. **H2 dla podsekcji**
   ```markdown
   ## SUM
   ## AVERAGE
   ## COUNT
   ```

4. **Obrazy dla wizualizacji**
   ```markdown
   ![[visualization.gif]]
   ```

5. **Komentarze w kodzie DAX**
   ```dax
   -- Obliczanie całkowitej sprzedaży
   Total = SUM(Sales[Amount])
   ```

### ❌ DON'T (Nie rób tego)

1. **Za dużo H1 w jednym pliku**
   ❌ 15 nagłówków H1 → 15 osobnych miar
   ✅ 3-5 nagłówków H1 → czytelna struktura

2. **Za dużo stron w jednej miarze**
   ❌ 10 separatorów `---` → 10 stron
   ✅ 3-5 separatorów → łatwa nawigacja

3. **Mieszanie tematów w jednym H1**
   ❌ `# Różne Funkcje` (SUM, LEFT, TODAY)
   ✅ Osobne H1 dla każdej kategorii

4. **Puste sekcje**
   ❌ `# Funkcje\n---\n# Inne`
   ✅ Zawsze dodaj treść między nagłówkami

5. **Brak obrazów dla skomplikowanych konceptów**
   ❌ Tylko tekst dla wizualnych danych
   ✅ GIF pokazujący proces krok po kroku

## 🔍 Debugowanie Problemów

### Problem: "Nie generuje się osobna miara dla H1"

**Przyczyna:** Brak pustej linii po H1
```markdown
# Funkcje
Treść zaraz po H1  ← ZŁE
```

**Rozwiązanie:** Dodaj pustą linię
```markdown
# Funkcje

Treść po pustej linii  ← DOBRE
```

### Problem: "Strony się nie dzielą"

**Przyczyna:** Separator musi być sam w linii
```markdown
Treść --- Treść  ← ZŁE
```

**Rozwiązanie:** `---` w osobnej linii
```markdown
Treść

---

Treść  ← DOBRE
```

### Problem: "DAX nie jest podświetlany"

**Przyczyna:** Brak oznaczenia języka
````markdown
```
Total = SUM(Sales[Amount])  ← ZŁE
```
````

**Rozwiązanie:** Dodaj `dax`
````markdown
```dax
Total = SUM(Sales[Amount])  ← DOBRE
```
````

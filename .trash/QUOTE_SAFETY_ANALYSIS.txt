1.1 HTML - ATRYBUTY ELEMENTÓW
================================================================================

TYP: class, id, data-xxx, aria-xxx, itp.

BEZPIECZEŃSTWO: ✓ 100% BEZPIECZNE dla prostych wartości

Prawidłowe zamiany:
  <div class="container">      =>  <div class='container'>
  <button id="btn1">           =>  <button id='btn1'>
  <input type="text">          =>  <input type='text'>

Wszystkie atrybuty HTML akceptują zarówno ' jak i " bez różnicy.

ZAGROŻENIE #1: Data atrybuty z apostrofami
  PROBLEM:
    <div data-tooltip="John's message"></div>
    Po zamianie:
    <div data-tooltip='John's message'></div>  <!-- BŁĄD! -->

  Parser HTML interpretuje to jako: data-tooltip='John'
  a następnie: s message' <- to już nie jest część atrybutu

  OCENA W PROJEKCIE: ✓ BEZPIECZNE
  Sprawdzenie: Wszystkie data-* atrybuty w projekcie nie zawierają apostrofów
  Przykład z projektu: data-id="123" -> data-id='123' OK

ZAGROŻENIE #2: JSON w atrybutach
  PROBLEM:
    <div data-config='{"color":"red"}'></div>
    JSON wymaga zawsze ", nie apostrofów wewnątrz

  OCENA W PROJEKCIE: ✓ BEZPIECZNE
  Sprawdzenie: Projekt nie używa JSON w atrybutach HTML
  Kod zawiera strukturę: onclick='changePage_5dc96cd3(-1)' <- bez JSON

1.2 HTML - EVENT HANDLERY (onclick, onload, itp.)
================================================================================

TYP: onclick="...", onchange="...", addEventListener(...)

BEZPIECZEŃSTWO: ⚠️ WARUNKOWE - zależy od zawartości handlera

ZAGROŻENIE #3: Event handler z zagnieżdżonymi stringami
  PROBLEM:
    <button onclick="alert('Hello')"></button>
    Po naiwnej zamianie:
    <button onclick='alert('Hello')'>  <!-- BŁĄD SKŁADNIOWY! -->

  Parser HTML widzi:
  - onclick = '
  - alert(
  - ' <- koniec atrybutu
  - Hello')
  - > <- brak przypisania

  PRAWIDŁOWA ZAMIANA:
    <button onclick='alert("Hello")'></button>  OK
  LUB:
    <button onclick="alert('Hello')"></button>  OK

  OCENA W PROJEKCIE: ✓ BEZPIECZNE
  Sprawdzenie: onclick='changePage_5dc96cd3(-1)'
  - Zawiera tylko: nazwę funkcji + liczbę
  - Brak stringów wewnątrz
  - Zamiana jest 100% bezpieczna

2.3 CSS - url() - ZAGROŻENIE!
================================================================================

ZAGROŻENIE #4: URL z apostrofami w ścieżce

  PROBLEM:
    background: url('C:\Users\John\'s Files\image.png');

  Parser CSS widzi:
    url('C:\Users\John\
    następnie: 's Files\image.png')
    To jest błędne!

  PRAWIDŁOWE ROZWIĄZANIA:
    background: url("C:\Users\John's Files\image.png");  /* " OK */
    background: url('C:\\Users\\John\'s Files\\image.png');  /* escape */

  OCENA W PROJEKCIE: ✓ BEZPIECZNE
  Sprawdzenie: CSS w projekcie nie zawiera url()
  background-image: url(...) nie jest używane

CZĘŚĆ 3: JAVASCRIPT - STRINGI I WYRAŻENIA
================================================================================

3.1 JavaScript - Proste stringi
================================================================================

BEZPIECZEŃSTWO: ✓ 100% BEZPIECZNE dla prostych stringów

Prawidłowe zamiany:
  const x = "text";       =>  const x = 'text';
  const x = "123";        =>  const x = '123';
  const x = "hello";      =>  const x = 'hello';

JavaScript traktuje ' i " identycznie dla prostych stringów.

================================================================================

3.2 JavaScript - Stringi z apostrofami (ZAGROŻENIE!)
================================================================================

ZAGROŻENIE #5: Apostrofem w stringu z apostrofami

  PROBLEM:
    const text = 'John\'s message';  <- OK
    const text = 'It's working';     <- BŁĄD!

  Parser JavaScript widzi:
    'It
    a następnie: 's working'
    To nie jest valid kod!

  PRAWIDŁOWE ROZWIĄZANIA:
    const text = 'It\'s working';    /* Escapowanie */
    const text = "It's working";     /* Zmiana na " */
    const text = `It's working`;     /* Template literal */

  OCENA W PROJEKCIE: ✓ BEZPIECZNE
  Sprawdzenie: Stringi w JavaScript:
    var vizId = '5dc96cd3';      /* Brak apostrofów wewnątrz */
    var containerId = 'viz_' + vizId;  /* Brak apostrofów */

  Wszystkie stringi to liczby, znaki specjalne (_,-) ale NIE apostrofy

================================================================================

3.3 JavaScript - Zagnieżdżone stringi (JSON)
================================================================================

ZAGROŻENIE #6: JSON wewnątrz JavaScript stringów

  PROBLEM:
    const json = '{"key":"value"}';   /* OK - " wewnątrz JSON */
    const json = "{'key':'value'}";   /* BŁĄD! JSON wymaga " */
    JSON.parse(json);  /* Wyrzuca: SyntaxError */

  PRAWIDŁOWE ROZWIĄZANIA:
    const json = '{"key":"value"}';   /* Apostrofem na zewnątrz OK */
    const json = "{\"key\":\"value\"}";  /* Escapowanie */
    const obj = {key: "value"};  /* JS obikt, nie JSON */
    JSON.stringify(obj);  /* Konwersja do JSON */

  OCENA W PROJEKCIE: ✓ BEZPIECZNE
  Sprawdzenie: Kod nie zawiera JSON.parse ani JSON.stringify
  window['showPage_5dc96cd3'] - to jest nawiasy z apostrofami, nie JSON

================================================================================

3.4 JavaScript - Template literals (ZAWSZE BEZPIECZNE)
================================================================================

BEZPIECZEŃSTWO: ✓ 100% BEZPIECZNE

Prawidłowe zamiany:
  const msg = `Hello "${name}"`;   <- bez zmian (backticks)
  const msg = `Hello '${name}'`;   <- bez zmian

Template literals (`) chronią przed zmianami i mogą zawierać zarówno ' jak i "

OCENA W PROJEKCIE: N/A
Projekt nie używa template literals w kodzie HTML

================================================================================

3.5 JavaScript - Regex wyrażenia
================================================================================

BEZPIECZEŃSTWO: ✓ 100% BEZPIECZNE

Prawidłowe zamiany:

  const re = new RegExp('test"word');  =>  new RegExp('test"word');
  const re = new RegExp("test'word");  =>  new RegExp('test\'word');

Apostrofem w regex literałach jest traktowany jako zwykły znak.

OCENA W PROJEKCIE: ✓ BEZPIECZNE
Sprawdzenie: Projekt nie zawiera zaawansowanych regex wyrażeń

CZĘŚĆ 7: EDGE CASES - Przypadki specjalne
================================================================================

Edge Case 1: Escape sequences
  "\n", "\t", "\\"
  To dzialają tak samo w ' jak w "
  const text = "line1\nline2";
  const text = 'line1\nline2';
  OK BEZPIECZNE

Edge Case 2: Unicode
  "\u0041", "\u{1F600}"
  To dzialają tak samo w ' jak w "
  const unicode = "\u0041";
  const unicode = '\u0041';
  OK BEZPIECZNE

Edge Case 3: HTML entities
  "&#39;" (apostrofy w HTML)
  Mogą być używane bez zmian
  <div title="John&#39;s">  => <div title='John&#39;s'>
  OK BEZPIECZNE

Edge Case 4: Eval (BARDZO NIEBEZPIECZNE!)
  eval('const x = "hello";');
  NIE NALEŻY UŻYWAĆ eval() w żadnym przypadku
  UNIKAĆ

Edge Case 5: Dynamiczne tworzenie HTML
  const html = '<button onclick="doSomething()">Click</button>';
  Wygenerowane HTML może mieć inne znaki niż string
  WYMAGA UWAZNOŚCI!

CZĘŚĆ 10: WERDYKT I REKOMENDACJA KONCOWA
================================================================================

PYTANIE: Czy zamiana wszystkich cudzysłowów " na apostrofy '
         jest bezpieczna i nie spowoduje błędów składniowych?

ODPOWIEDZ SZCZEGÓŁOWA:

1. OGÓLNIE: NIE - istnieją zagrożenia w:
   - Event handlerach z zagnieźdżonymi stringami
   - Data atrybutach z apostrofami
   - JSON w HTML
   - CSS url()
   - JavaScript stringach z apostrofami

2. DLA TEGO PROJEKTU: TAK - całkowicie bezpieczna, ponieważ:
   - Kod już konsekwentnie używa apostrofów
   - Event handlery mają tylko nazwy funkcji (brak stringów)
   - Brak JSON w atrybutach
   - Brak CSS url()
   - Brak apostrofów w JavaScript stringach
   - Wszystkie stringi to liczby i znaki specjalne

3. PRAKTYCZNIE:
   - Użyj automatycznego formatera (Prettier)
   - Ustal standard w projekcie
   - Nie mieszaj stylów
   - Zweryfikuj krityczne miejsca przed zmianą
   - Zastosuj linting rules

REKOMENDACJA:
  OK DLA TEGO PROJEKTU - bezpieczna zamiana
  NIE DLA INNEGO KODU - wymaga indywidualnej analizy każdego zagrożenia
  OK NAJLEPSZE - użycie Prettier z konfiguracją "singleQuote": true
